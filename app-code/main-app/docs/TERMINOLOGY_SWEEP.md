# Terminology sweep — make every screen use the store's own words

_11 Sep 2026. Generated by an audit of `resources/js` (public site, legal pages, Super Admin and Platform excluded)._

## Where this stands

- **Words per business**: `config/business_types.php` gives each of the 85 business types its words (Clients, Jobs, Plumbers, Parts, Members…). `StoreProvisioner` writes them to `tenant_terminology` at signup, and `HandleInertiaRequests` shares them to every page as `props.terms`.
- **Already on the store's words**: the builder (it shows them before signup), the sidebar (`useNavLabel` in `SidebarItem`), the module nav (`ModuleNavBuilder`), and the 8 screens marked `yes` below.
- **Still hard-coded**: 161 files and 598 visible strings, listed below — most-affected first.

## Recipe (mechanical, one file at a time)

```jsx
import { useTermText } from '@/lib/terms';
const tt = useTermText();
<h1>{tt('Customers')}</h1>          // 'Clients' for a law firm
<Button>{tt('Add Product')}</Button>  // 'Add Part' for a garage
```

Wrap **visible text only** — never route names, API field names, permission keys or values sent to the server. `tt()` leaves any word the store has not renamed exactly as written, so a wrapped screen looks identical for a store on default words.
