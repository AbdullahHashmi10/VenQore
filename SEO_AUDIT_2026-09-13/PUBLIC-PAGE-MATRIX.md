# VenQore V6 Public-Page Positioning Matrix

This matrix covers the complete source-controlled public estate by page family. It prevents 114 separate rewrites from becoming 114 different versions of the product story.

## Universal rules for every indexable page

- Use “VenQore is the AI ERP builder” as the category anchor where category context is needed.
- Give each page one primary search intent and one user-visible H1.
- Use one explanatory subhead, not multiple stacked ledes.
- Explain how the page-level capability participates in the assembled system.
- Use exact facts from registries/configuration.
- Use one CTA vocabulary and destination.
- Give every page a self-canonical, unique title/description, breadcrumb path, and appropriate OG image.
- Do not use “never breaks,” unverifiable “battle-tested,” unsourced competitor facts, or ambiguous test counts.

## Docs and help family — approximately 28 pages

### Docs template

- H1 states the technical outcome.
- Opening answer is 40–80 words and immediately defines the feature/task.
- Prerequisites, steps, example, edge cases, related configuration, and next link.
- Named owner/reviewer, `dateModified`, TechArticle, BreadcrumbList.
- Link technical concepts to Blueprint/Ledger/Reckoner only when relevant.

### Help template

- Lead with the user task, not product marketing.
- Numbered resolution steps, screenshots with descriptive alt, expected result, troubleshooting branch, support escalation.
- No forced keyword repetition.
- Link to one relevant product page and one next help task.

### Index decision

Index durable, self-contained answers. Noindex account-specific, thin, duplicate, temporary, or status-only content that would not satisfy a search visitor.

## Blog family — index plus approximately 13 fallback posts

### Role

Build authority around the problems the product uniquely solves, not generic small-business advice.

### Required editorial pattern

- Direct answer/definition first.
- Real operational example, calculation, screenshot, or data table.
- Named author and reviewer where financial/accounting claims are involved.
- Sources for changing facts.
- Original point of view tied to the assembled-system and one-ledger thesis.
- Relevant internal links to one hub, one product proof page, and one adjacent article/tool.
- Article-specific OG image.

### Priority clusters

1. AI ERP builder and composable ERP.
2. POS-to-ledger correctness.
3. Inventory valuation, FIFO, batch, expiry, and COGS.
4. Multi-store/multi-channel stock truth.
5. Industry workflow design.
6. Human-reviewed operational AI.

## Tools family — hub plus approximately 32 indexable tool URLs

### Role

Tools should win task-intent searches, complete the task without signup, and then show the next operational problem VenQore removes.

### Shared tool template

1. H1 naming the exact free task.
2. Interactive tool immediately visible.
3. Concise result explanation.
4. One worked example.
5. Limits/assumptions/data privacy.
6. Related tool links.
7. Contextual bridge: “VenQore’s [module] performs this from live operational data.”
8. One builder CTA, not an old trial/register CTA.

### Tool groups and bridge copy

| Group | Representative URLs | VenQore bridge |
|---|---|---|
| Barcode/QR | generator, validator, nine barcode-format children, QR menu | Product catalog, labels, POS scanning, live menu/catalog data. |
| Documents | invoice, receipt, quote, purchase order, packing slip, credit note | Documents module and automatic ledger/stock effects. |
| Labels/sheets | label sheet, price tag, stock count, cash drawer count | Inventory and POS operations from live records. |
| Calculators | margin, food cost, payment fee, POS ROI | Reckoner/dashboard metrics calculated from actual transactions. |
| Data tools | SKU generator, product CSV cleaner, inventory health | Catalog setup, imports, replenishment, inventory controls. |
| Capture | SmartCapture tool | Reviewed extraction into purchasing/documents/ledger. |

Remove the approximately 20 `HowTo` JSON-LD objects. Keep instructional visible content, but use SoftwareApplication + BreadcrumbList and selective visible FAQ markup.
