# Test remediation — 2026-08-03

51 failures. Two root causes explain 49 of them. Neither was a new defect; both were
introduced by the previous session's changes.

---

## Why it got worse (103 → 13 → 51)

### Cause 1 — `reverseEntry()` stopped flagging the reversal (47 failures)

The previous pass changed `AccountingService::reverseEntry()` so the mirror-image
reversal entry was **no longer** marked `is_reversed = 1`, reasoning that the field
means "this entry was undone", which is false for the entry doing the undoing.

That reasoning is wrong for this codebase. Roughly 40 call sites — `ReportController`,
`DashboardController`, `PartyController`, `LedgerService`, `getBalance()` — filter
`WHERE is_reversed = 0`, and the semantics they rely on are *"this row is part of an
undone pair, ignore it"*. `ExpenseController::update()` and `PurchaseController` post
their reversals the same way.

Flagging only the original left the mirror visible, so every balance netted to
**minus** the original instead of zero.

**Proof.** Every failing Golden number is one transaction — `TXN-SAL-002`, the credit
sale of 3 phones to Ahmed, reversed by `TXN-SR-001` at seeder line 612:

| Account | Reported | Manifest | Δ | Source |
|---|---|---|---|---|
| 4000 Revenue | 1,456,930.00 | 1,578,430.00 | 121,500.00 | 3 × 45,000 − 10% |
| 2100 Output tax | 241,150.10 | 261,805.10 | 20,655.00 | 121,500 × 17% |
| 1200 AR | 144,840.10 | 286,995.10 | 142,155.00 | 121,500 + 20,655 |
| 5000 COGS | 1,059,000.00 | 1,155,000.00 | 96,000.00 | 3 × 32,000 |
| 1100 Inventory | 524,500.00 | 428,500.00 | −96,000.00 | stock put back |

Derived figures reconcile too: total assets Δ 46,155 (= 142,155 − 96,000), gross and
net profit Δ 25,500 (= 121,500 − 96,000), trial balance ΣDR Δ 142,155.

**Fix.** `is_reversed = 1` restored on the reversal, *in addition to*
`is_reversal` / `reverses_entry_id`. The previous pass was right that those audit-link
columns needed populating — F-17 joins on `reverses_entry_id` and went green because of
it. Both are now set, so F-17 stays green and the balance queries are correct.

Also added a guard in `GoldenVerifyCommand`: an entry that is itself a reversal
carries `is_reversed = 1` but legitimately has no `reversed_by` pointer.

### Cause 2 — the dashboard never ran the sync (the rest, and the 1330)

`FinalTester/tests` is a **materialised view** of `Tester/tests`
(`FinalTester/Scripts/sync.php`, documented in `FinalTester/bootstrap.php`).
`Scripts/run.bat` runs the sync as step 2. **`FinalTester/dashboard/server.js` did
not.**

So every edit written to `Tester/tests` last session was invisible to the run:
I-05's `TXN-` filter, S-054, `SuiteIntegrityTest` — all still failing with their old
messages — and the **six recovered marketing test files sat on disk uncounted**. That
is the answer to "why is it still 1330": Pest was reading a stale copy.

**Fix.** `server.js` now calls `sync.php` before discovery and *blocks* the run if the
sync fails, rather than silently executing a stale tree. Both trees are now identical:
204 test files, zero drift in either direction.

> Note on the two counts: 1417 is a regex count of test *methods* on the filesystem;
> Pest collects fewer because base/abstract classes and helper `test(` occurrences are
> counted by the regex but are not runnable tests. They measure different things and
> will never be equal. The old `1583` was a hand-maintained figure and was simply stale.

## The one thing still red, and why it should stay red

`MigrationTest` fails with `PDOException: could not find driver`. The Vyapar importer
reads a customer's Vyapar **backup file**, which is SQLite. That does not violate the
MySQL-only policy — that policy governs VenQore's own database — but it does need
`pdo_sqlite`.

Without the extension the Vyapar import is dead on any host configured this way,
**including production**. Skipping it would convert a live product outage into a silent
green, so the test now fails immediately with the exact remedy instead of a bare PDO
error.

```ini
; enable both, then restart the PHP process
extension=pdo_sqlite
extension=sqlite3
```

Candidate `php.ini` files on this machine:

```
C:\Users\PC\AppData\Roaming\Local\lightning-services\php-8.2.23+0\bin\win64\php.ini
E:\Software\Xampp\php\php.ini
```

Verify with `php -m | findstr sqlite`.
