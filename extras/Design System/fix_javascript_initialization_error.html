02 · Principles

The laws that survive every version.

1 · No raw values in components

Colours, radii, z-index and other system values live in tokens. If a component needs a value that is not a token, the system is missing a token.

2 · Teal is the brand

Primary actions, focus, identity and active states use VenQore teal. Semantic colours and AI colour do not compete with the brand.

3 · Module colour is wayfinding

Module colour tells the user where they are. It belongs in chrome, navigation, headers, breadcrumbs and module accents (never inside financial data).

4 · Meaning is never colour alone

Negative values also get a minus sign and parentheses. Status gets an icon or dot and a word. Colour reinforces meaning; it does not carry it alone.

5 · Marketing may be expressive. Product may not.

Public pages can use ambient motion, expressive typography and a richer visual stage. The product prioritizes clarity, data, touch targets and controlled state feedback.

13 · Data visualisation

Charts: one system, fixed colour order.

Library policy

Standardize on Chart.js / Canvas. Chart containers are responsive and bound cleanly to container heights. Standardize colors across analytical modules.

Consolidating Chart.js options establishes uniform axes, tooltips, and series colours across all analytics views.

Example series order

Fixed order · never randomly cycle the palette · ninth series folds into Other.

RuleDecision
Series orderFixed slots; slot 1 is VenQore teal.
More than eight seriesFold into Other, facet, or redesign; never keep cycling colours.
Diverging chartsTwo hues + neutral grey midpoint. Never a saturated hue at zero.
Sequential dataOne hue light to dark; teal ramp is preferred for brand-aligned magnitude.
Dual-axis chartsAvoid unless the analytical case is truly unavoidable.
AnimationPrefer state transition; never count a financial KPI as if it were a game score.

15 · Applied

Governing rule: ReactBits is primarily a marketing dependency. Inside the ERP it is allowed only when the animation communicates useful load or execution state.
AnimatedListLanding · business category picker

Keep. Good for choosing among categories. Cap visible items; keep keyboard navigation.

ShinyTextLanding · hero prompt

Keep once. Indicates active input field clearly.

FoldTextLanding · hero headline

Keep once on first paint. Never re-run on scroll.

LaserFlowLanding · footer watermark

Keep as a single page signature.

OptionWheelLanding · alternate picker

Choose one picker pattern, not competing answers to the same action.

SplitTextApp

Remove. Animating headings inside an ERP adds motion without information.

Remove. Scrambling readable financial/UI text is hostile to clarity.

17 · Ship it

The bugs and problems we found.

Critical · launch blocker

Customizer/debug drawer is exposed

Vorticity, splat force, pressure iterations and dye resolution controls appear on a public-facing page. Gate it behind ?debug=1 or remove it from production.

Critical

Template copy is still present

Placeholder copy like "VenQore: Design with AI" and "future of creativity" must be completely replaced with true ERP product positioning.

Critical

Dark-mode accent text contrast failure

#327882 used as text on dark backgrounds yields a 3.88:1 failure. Use #5DA5B0 for accent text on dark surfaces.

High

Sidebar hover clipping

overflow-hidden on the row combined with group-hover:scale-125 on the icon clips the icon and hover ring. Remove the transform/clip conflict.

High

Collapsed tooltip clipping

The tooltip sits inside an overflow-clipped parent even though it is positioned at left-full. Port it to body; z-index cannot escape the clipping ancestor.

High

Fluid canvas covers the gradient layer

The original build placed the canvas above the intended gradient. Restack layers or convert overlay into controlling scrim.

High

Tailwind CDN on production

Build and ship compiled production stylesheets rather than the CDN script.

Systemic

31 z-index values

Codemod to named token layers.

Systemic

~20 corner radii

Collapse to the final 12px / 20px / full visual vocabulary.

Systemic

184 hover-scale usages

Delete them except for the explicitly approved media-thumbnail pattern.

20 · Master Card Dimension Rules & Possibilities

1920px 12-Column Master Card Sizing System

Strict boundary contracts, modular mathematical formulas, and all valid dimensional possibilities across the 4 core card categories on a 1920px baseline (12-column system, 114px base column, 24px gutter, and 64px vertical height increments).

1920px Master Baseline 12 Columns (114px + 24px Gutter) Height Multiples of 64px (No Row Gutters) Dual Representation: Grid (H × W) & Pixels (W × H)
1. Width Calculation Formula
Width(W) = (W × 114px) + ((W - 1) × 24px)

Where W represents the column width span (1 to 12). Base column = 114px, Column gutter = 24px.

2. Height Calculation Formula
Height(H) = H × 64px

Where H represents the vertical row multiplier. Height is calculated strictly as pure multiples of 64px (no row gutters).

📐 Sidebar Interaction & Responsive Bounds Enforcement:

1. When the sidebar is expanded (240px at 1920px), the 12-column workspace spans exactly 1632px.
2. When the sidebar is retracted (76px icon rail), the workspace expands to calc(100% - 76px). Cards fluidly adapt but must respect their category hard boundaries: they cannot shrink below their minimum pixel floor or expand beyond their maximum pixel ceiling.
3. All layout states are tracked both by Grid Ratio / Units (e.g. 1 × 4, 2 × 3) and by Exact Pixel Dimensions (e.g. 528px × 64px, 390px × 128px) to guarantee pixel-perfect rendering across the ERP.
