# Known Limitations

Honest accounting of what is NOT done, or not verifiable in this environment. Listed so
nothing is a silent gap.

## 1. Dynamic execution could not be run here (the biggest one)

The implementation sandbox has **no PHP and no MySQL runtime**. Everything was authored and
**statically verified** (PHP structure, no NUL bytes, no duplicate FQCNs, valid
XML/YAML/JSON, and Python simulations that reproduce each meta-test's logic and each
financial derivation). These require an on-machine run to become *dynamic* proof:

- The **3 consecutive green runs** (Phase A exit) — `vendor\bin\phpunit -c Tester\phpunit.xml`.
- The **mutation score (MSI)** — `infection.json5` is ready; the score is generated by
  running Infection on-machine.
- The **concurrency race** and **trigger** and **corruption-alert** tests — they need a live
  MySQL to exercise row locks, triggers, and the scheduler.

The Python simulations give high confidence the logic is correct (e.g. the calculator
derivation reproduces all 24 declared sale values across both datasets; all 5 registry-drift
checks pass; the gate self-test logic fires correctly), but simulation is not execution.

## 2. Production bug FIXES are out of scope (by design)

POS-003 (COGS fabrication) and WOO-001 (webhook posts no journal) are **application** bugs.
The platform's job is to PIN them red in the quarantine lane with expiring waivers, which it
does. Fixing the app code is a separate ticket owned by the app team. The pinning tests will
turn green automatically once the bugs are fixed (or fail loudly when the waivers expire on
2026-10-11).

## 3. Field-name assumptions in new tests

Some new production-path tests (legacy POS payload, Woo payload, concurrency fixture) use
schema field names inferred from the surrounding suite. When first run on-machine, a few may
need field-name adjustment to the exact live request/table contract. They are written to
skip honestly (not pass vacuously) where a fixture is missing.

## 4. Permission ratchet is frozen, not yet burning down

The 257-route debt is checksum-locked and the ceiling is enforced, but the classification
pass (tag each route needs-permission / intentionally-public) is marked `pending` in
`permission_ratchet.yaml`. The burndown tranches (257→200→120→40→0) are planned, not yet
executed — that is per-release application work.

## 5. Multi-currency (FX) — explicit non-goal for now

Per blueprint §12, FX is registered as **out of scope** pending product confirmation. If FX
ships, it becomes Golden Company 3 with its own hand-derived spec. This is an explicit
non-goal, not a silent gap.

## 6. The mount write hazard (environmental, mitigated)

This environment intermittently truncated file writes and appended trailing NUL bytes. Three
suite-breaking truncations left by a prior session were found and repaired
(`VenQoreTestCase.php`, `phpunit.xml`, `SaleInputVerificationTest.php`), and a NUL-safe
write+verify protocol was used thereafter. A final full-repo sweep confirms zero NUL bytes
and balanced braces across all touched files — but anyone re-editing these files should
re-run the sweep in `RUN_INSTRUCTIONS.md`.
